# シリアルポートプロトコル

添付ファイル内の命令词播报词协议列表V1_中文ファイルを開くと、送信プロトコルと受信プロトコルを確認できます、

## 1.機能エントリーの解析

ファイルから 10 個の機能エントリーの送信プロトコルと受信プロトコルを確認できます、

![図 1](../../../../../public/images/tutorials/accessories/ai-voice-module/Serial-Protocol/1.png)

機能エントリーは、プロトコルの 3 番目のバイトを解析することで区別できます

![図 2](../../../../../public/images/tutorials/accessories/ai-voice-module/Serial-Protocol/2.png)

このうち 1 番目と 2 番目のバイト（EF EF）はフレームヘッダーを表し、3 番目のバイトは機能ワードの ID を表し、4 番目のバイトはコマンドワードの ID を表し、5 番目のバイト（EE）はフレームエンドを表します

## 2.コマンドエントリー

コマンドエントリーの例は以下のとおりです。コマンドの 4 番目のバイトが ID を表します

![図 3](../../../../../public/images/tutorials/accessories/ai-voice-module/Serial-Protocol/3.png)

例：

例えばモジュールに 小车停止 と言うと、モジュールはシリアルポートを通じて FE EF 00 01 EE の 5 バイトを送信します。ホストコントローラのシリアルサービス関数でこのデータ群を取得でき、その後 4 番目のバイトを解析すると ID:01 が得られるので、この時点で 小车停止 であることがわかります。

## 3.再生フレーズエントリー

再生フレーズエントリーはアクティブには再生されず、必ずホストコントローラがシリアルポートを通じてコマンドを送信した場合にのみ再生されます（コマンドエントリーの再生フレーズも再生できます）。

![図 4](../../../../../public/images/tutorials/accessories/ai-voice-module/Serial-Protocol/4.png)

このうち 1 番目と 2 番目のバイト（FE EF）はフレームヘッダーを表し、3 番目のバイトは再生機能の FF を表し、4 番目のバイトは再生する内容の ID を表し、5 番目のバイト（EE）はフレームエンドを表します

例：

私たちが “初始化完成” を再生する必要がある場合、ホストコントローラはシリアルポートを通じて FE EF FF 67 EE を音声対話モジュールに送信する必要があります。送信が完了すると、音声対話モジュールは “初始化完成” を再生します

![図 5](../../../../../public/images/tutorials/accessories/ai-voice-module/Serial-Protocol/5.png)
