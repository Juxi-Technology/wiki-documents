# トラブルシューティング

> **[ストアで購入](https://www.juxitech.com/ja/products/2-dof-servo-pan-tilt-unit)**

本章では、よくある問題と解決方法をまとめ、使用中に発生するさまざまな問題を素早く切り分けて解決できるようにします。

---

## ハードウェア関連の問題

### サーボが応答しない

**考えられる原因：**
1. サーボ電源が接続されていない
2. サーボとドライバボードの接続不良
3. シリアルポートの接続に失敗している
4. サーボが有効化されていない
**解決方法：**
1. サーボ電源が正しく接続され、通電しているか確認します
2. サーボとドライバボードの接続ケーブルが確実に固定されているか確認します
3. `examples/diagnostic.py` を実行して診断情報を確認します
4. `C` を押してジンバルに接続済みで、サーボが有効化されていることを確認します

### サーボの動作方向が逆

**考えられる原因：**
- サーボの取り付け方向、またはプログラムの制御パラメータの調整が必要です
**解決方法：**
`src/trackers/tracking_controller.py` の `calculate_move` メソッドを修正し、該当するパラメータの符号を反転します：

# 左右が逆の場合

```python
delta_pan = -int(self.kp_pan * err_x)
```

# 上下が逆の場合

```python
delta_tilt = -int(self.kp_tilt * err_y)
```

### サーボが振動する

**考えられる原因：**
- トラッキングパラメータが敏感すぎる
- デッドゾーン範囲が小さすぎる
- サーボの負荷が大きすぎる、または電力供給が不足している
**解決方法：**
1. `dead_zone` パラメータを大きくします
2. `min_move_interval` を大きくします
3. `kp_pan` と `kp_tilt` を小さくします
4. 電源電圧が正常か確認します

### シリアルポートの接続に失敗する

**考えられる原因：**
- ドライバがインストールされていない
- シリアルポート番号が正しくない
- シリアルポートが他のプログラムに占有されている
- 接続ケーブルの故障
**解決方法：**
1. Windows ではデバイスマネージャーを確認し、ドライバが正常にインストールされていることを確認します
2. `examples/list_ports.py` を実行して正しいシリアルポートを探します
3. シリアルポートを占有している可能性のある他のプログラムを終了します
4. USB ポートまたはケーブルを交換して試します

## ソフトウェア関連の問題

### カメラが開けない

**考えられる原因：**
- カメラインデックスが正しくない
- カメラが他のプログラムに占有されている
- カメラのハードウェア接続の問題
- カメラドライバの問題
**解決方法：**
1. `examples/list_cameras.py` を実行して利用可能なカメラのインデックスを確認します
2. カメラを使用している可能性のある他のプログラムを終了します
3. カメラの接続が正常か確認します
4. USB ポートを交換して試します

### OpenCV のエラー

**考えられる原因：**
- OpenCV のバージョンの問題
- 依存ライブラリのインストールが不完全
- カメラのハードウェア異常
**解決方法：**
1. 依存ライブラリを再インストールしてみてください：

```python
pip install --upgrade opencv-python numpy
```

1. Python バージョンが要件（>=3.8）を満たしているか確認します
2. エラースタック情報を確認し、問題のあるコードを特定します

### 依存関係のインストールに失敗する

**考えられる原因：**
- pip のバージョンが古い
- ネットワーク接続の問題
- 権限の問題
**解決方法：**
1. まず pip をアップグレードします：

```python
pip install --upgrade pip
```

1. 中国国内のミラーを使用して高速化します：

```python
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

1. ネットワーク接続が正常か確認します

### プログラムの起動が遅い

**考えられる原因：**
- Windows で DSHOW を使用していない
- カメラのハードウェア初期化に時間がかかる
**解決方法：**
1. コードでカメラバックエンドとして `cv2.CAP_DSHOW` を使用していることを確認します
2. 他のプログラムがカメラを占有していないか確認します
3. 数秒待ってください。カメラの初期化には通常ある程度の時間がかかります

## トラッキング関連の問題

### ターゲットの認識が不正確

**カラートラッキングの場合：**
- ターゲットの色と背景のコントラストが明確か確認する
- 色パラメータを調整する（`src/detectors/color_detector.py` 内）
- 光が十分で均一であることを確認する
**顔トラッキングの場合：**
- 光を十分に確保し、逆光を避ける
- 顔をカメラに正面向きにする
- 適切な距離を保つ

### トラッキング時にジンバルが動かない

**考えられる原因：**
1. ジンバルに接続していない
2. ターゲットをロックしていない
3. ターゲットがデッドゾーン内にある
4. プログラムでエラーが発生している
**解決方法：**
1. `C` を押してジンバルに接続済みであることを確認します
2. `T` を押してターゲットをロック済みであることを確認します
3. コンソール出力を確認し、エラーメッセージを探します
4. ターゲットが `dead_zone` の範囲内にあるか確認します

### トラッキングの方向が逆

**解決方法：**
「サーボの動作方向が逆」の解決方法を参照してください。

### トラッキング時の振動

**解決方法：**
「サーボが振動する」の解決方法を参照してください。

### ターゲットロックに失敗する

**考えられる原因：**
1. ロック時にターゲットが画面中央にない
2. ターゲットが小さすぎる、または色が目立たない
3. ターゲットが検出されていない
**解決方法：**
1. ロック時にターゲットが画面中央にあることを確認します
2. ターゲットが適切な大きさで、正しく検出できるようにします
3. コンソール出力を確認し、ターゲットが検出されているかを確かめます
4. ターゲットの位置を調整し直してからロックします

## 診断ツールの使用

### 診断プログラムの実行

システムには総合的な診断ツールが用意されており、システム全体のハードウェアをテストできます：

```python
python examples/diagnostic.py --camera 0 --port COM3
```

診断プログラムは以下を順にテストします：
1. カメラが正常に動作するか
2. シリアルポートが正常に接続できるか
3. サーボが正常に応答するか
診断が完了するとテスト結果が表示され、問題の特定に役立ちます。

### デバッグ出力の確認

プログラムの実行中、コンソールに関連するデバッグ情報が出力されます。内容は以下のとおりです：
- 検出されたターゲット情報
- ターゲット座標
- 誤差値
- ジンバル移動指令
- エラー情報全般
これらの出力を注意深く観察することで、問題を素早く特定できます。

## 復旧方法

### ジンバルを安全な位置に戻す

- `R` を押してジンバルを中央に戻す
- または `gimbal.return_to_center()` を呼び出す

### すべての設定をリセット

- `S` を押してトラッキングを停止する
- `R` を押して中央に戻す
- ターゲットを再度ロックする

### 再キャリブレーション

トラッキング効果が著しく悪い場合は、以下を行えます：
1. トラッキングパラメータを調整する
2. ターゲットを再度ロックする
3. 必要に応じてプログラムを再起動する
4. ハードウェア接続を確認する

## サポートを受けるには

上記の方法で問題が解決しない場合は、以下の情報を記録してください：
- オペレーティングシステムの情報
- Python のバージョン
- 詳細なエラーメッセージ
- 問題を再現する手順
- diagnostic を実行した結果
