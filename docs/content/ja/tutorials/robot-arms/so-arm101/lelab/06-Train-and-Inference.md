# 6 · 訓練と推論

> **前へ:** [05 データセットの記録](05-Record-Dataset.md)
> **次へ:** [07 トラブルシューティング](07-Troubleshooting.md)

訓練はデータセットを**ポリシー**にします——カメラ画像を関節位置に写像するモデルです。推論はそのポリシーをフォロワーアームで実行します。

## 訓練

**Training** タブを開き、選びます：

| 選択項目 | 備考 |
|---|---|
| **Dataset** | ローカルのデータセット、または Hub 上のもの |
| **Policy type** | 単腕では通常 **ACT** が最初の選択です。Diffusion Policy、SmolVLA、π₀ ファミリーも利用できます |
| **Where to run** | このマシン、または Hugging Face のクラウドジョブ |
| **Training length** | ステップ数。多ければ良いと決めつけず loss を注視します |

タブは訓練ログを配信し、チェックポイントが書かれた順に表示します。

### ローカルかクラウドか

| | ローカル | Hugging Face クラウドジョブ |
|---|---|---|
| 必要なもの | このマシンの GPU | アクセス権のある Hugging Face アカウント |
| 速度 | あなたの GPU 次第 | ジョブごとに選ぶ固定マシン |
| 向いている用途 | 小規模データセット、試行 | 長時間の実行 |

クラウドの選択肢があるからこそ、ワークフローの残りはノート PC で足ります——ローカルで記録し、リモートで訓練します。

### ポリシーの追加要素

一部のポリシータイプは、LeLab がデフォルトでインストールしない依存関係を必要とします。選ぶとインストールを促されるので、承諾してバックグラウンドインストールが終わるのを待ってからジョブを開始してください。同じ仕組みが任意の訓練用追加要素にも当てはまります。

## チェックポイント

訓練はチェックポイントを最後だけでなく定期的に書き込むので、中断された実行でも使えるモデルが残ります。各チェックポイント名にはそのステップ番号が含まれます。loss が上昇し始めたら、より早いものを試してください。

## 推論

**Inference** タブを開きます：

1. 両アームが接続されキャリブレーション済みであることを確認します。
2. **ポリシー**を選びます——ローカルのチェックポイント、または Hub 上のモデル。
3. **カメラ**とその **rotation** を確認します。
4. 推論を開始し、作業空間を片づけます。

### カメラの rotation と割り当て

**記録時と同じ rotation を使ってください。** よく訓練されたポリシーが実機で何の役にも立たない最も一般的な原因で、しかも何も警告してくれません：0° と 180° は同じ画像寸法を生みます。

カメラの**割り当て**にも同じことが言えます。記録時に `wrist` と呼ばれていたカメラが今は別の物理カメラなら、ポリシーは間違った画像を見ています。

それらがすべて正しくてもアームが機能しないなら、もう一度データセットを見てください——[5 ページ](05-Record-Dataset.md)を参照。

### 介入

アームに手を伸ばす前に推論を停止します。手で加えた修正は、新しいエピソードを記録して再訓練しない限り訓練信号にはなりません。

## リプレイ

リプレイは記録済みのエピソードをフォロワーアームで再実行します。記録した関節位置を再生するので、ポリシーが悪くても正しく見えます——これはハードウェアとデータセットを確認するもので、ポリシーを確認するものではありません。ポリシーが何をするかは推論で見てください。
