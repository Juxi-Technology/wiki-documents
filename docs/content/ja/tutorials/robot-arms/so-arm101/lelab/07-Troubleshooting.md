# 7 · トラブルシューティング

> **前へ:** [06 訓練と推論](06-Train-and-Inference.md)

症状別にまとめています。

## ページが開かない、またはポートが使用中

ポート **8000** と **8080** は LeLab のものです。古いプロセスがよくある原因です——`Ctrl+C` ではなくターミナルを閉じて終了したプロセスです。

```bash
lelab --stop
```

両方のポートを解放します。起動前に確認するには：

```bash
curl http://localhost:8000/health
```

JSON の応答が返れば、8000 で何かが動いています。

## `--dev` モードでページが空白または 404

Vite は **:8080** で UI を提供し、API は **:8000** で動きます。`:8080` を開いてください。`--dev` のポート 8000 では UI なしの API しか得られません。

## アームが表示されない

ポートがあなたのユーザーから見えるか確認します。Linux では、グループが欠けているとアームが無いように見えます：

```bash
ls /dev/ttyACM*
groups | grep dialout
```

`dialout` が無い場合は：

```bash
sudo usermod -aG dialout $USER
```

その後**ログアウトして再ログイン**します——グループはログイン時に読まれるので、新しいターミナルでは足りません。

### アームが 1 本しか見つからない

ハブではなく**2 つの別々の USB ポート**を使ってください。両アームは同じ種類のデバイスとして列挙され、共有ハブでは不安定に提示されることがあります。ポートを特定するには、一方のアームを抜いてどの一覧項目が消えるか確認します。

## 毎回キャリブレーションし直すことになる

キャリブレーションファイルは `~/.cache/huggingface/lerobot/`、つまり `~/.cache/` の下にあります。キャッシュを消去するツールやコンテナの再起動がこれらを奪います。

- `~/.cache/huggingface/lerobot/calibration/` を持続的な場所にバックアップします。
- コンテナ内では、そのディレクトリをボリュームとしてマウントします。

### 再キャリブレーションを求めずにキャリブレーション済みのアームがおかしく動く

選択した**プロファイル**がその物理アームのものか確認します。プロファイルは 1 本のアームのゼロ点に結びついています。アームを入れ替えると再キャリブレーションが必要です。

## カメラ映像が逆さままたは横倒し

[Calibration タブ](03-Calibration.md)でカメラの **Rotation** を設定します：0°、90°、180°、270°（時計回り）。逆さまのリストカメラは 180° です。

**90° と 270° は出力の寸法を入れ替えます**——640 × 480 のキャプチャは 480 × 640 になります。

## 訓練済みポリシーが役に立たない

順に——最初の 2 つは、悪い訓練実行よりはるかに一般的です：

1. **カメラの回転。** 推論が記録時に使った回転を使っているか確認します。0° と 180° は同じ画像寸法なので、何も警告してくれません。
2. **カメラの割り当て。** 記録時に `wrist` だったカメラが今は別の物理カメラなら、ポリシーは間違った画像を見ています。
3. **開始位置とタスク記述。** 推論は実演が始まった配置から始めなければなりません。
4. **チェックポイント。** より早いものを試してください。

## スマートフォンをカメラとして使う

ブラウザがカメラアクセス（`getUserMedia`）を許可するのは **HTTPS** 経由のみで、`localhost` を除きます。したがって LAN 経由で接続するスマートフォンは拒否されます。

セットアップガイド：[`frontend/HTTPS_SETUP.md`](https://github.com/Juxi-Technology/leLab/blob/main/frontend/HTTPS_SETUP.md)。証明書は自己署名なので、ブラウザが承諾を求める警告を表示します。

デフォルトのインストールでは **HTTPS** 付きで起動しません。スマートフォンカメラには、そこに書かれた証明書フラグ付きの手動起動が必要です。

## データセットが開けない——「まだダウンロードされていません」

LeRobot は記録が**正常に終了**したときにデータセットインデックスを書き込みます。エピソードの途中で kill されたセッションは、完全に見えてそうでないディレクトリを残すことがあります。エピソードのデータは通常まだディスク上にあり、欠けているのはインデックスです。セッションを記録し直し、停止ボタンで停止してください。

## 訓練でパッケージが無いと言われる

一部のポリシータイプと任意の訓練機能は、デフォルトではインストールされない依存関係を必要とします。Training タブは、それを選ぶとインストールを提案します。ジョブを開始する前にバックグラウンドインストールが終わるのを待ってください。手動でインストールしたい場合、訓練ログにパッケージ名が出ます。

## 更新通知が表示されない

設計上そうなっています。チェックは git からのインストールにのみ適用されます。**編集可能インストール**（`pip install -e .`）は作業コピーであり、チェックされません。`git pull` で更新してください。

## それでも解決しない

**ブラウザコンソール**と**`lelab` を実行しているターミナル**を集めてください——サーバは失敗したリクエストを記録します。これらほとんどの障害は、最後に変えたものから 1 歩しか離れていません。
