# 6 · 训练与推理

> **上一篇**：[05 录制数据集](05-Record-Dataset.md)
> **下一篇**：[07 常见问题](07-Troubleshooting.md)

训练把数据集变成**策略**——一个把摄像头画面映射成关节位置的模型。推理把策略放到从臂上跑。

## 训练

打开 **Training** 页，选：

| 项目 | 说明 |
|---|---|
| **数据集** | 本地数据集，或 Hub 上的 |
| **策略类型** | 单臂通常先试 **ACT**。也能用 Diffusion Policy、SmolVLA、π₀ 系列 |
| **在哪跑** | 本机，或 Hugging Face 云端任务 |
| **训练步数** | 盯着 loss 看，不要假设越多越好 |

页面会实时滚训练日志，checkpoint 写出来也会显示。

### 本地还是云端

| | 本地 | Hugging Face 云端任务 |
|---|---|---|
| 需要 | 本机有 GPU | 可用的 Hugging Face 账号 |
| 速度 | 看你的 GPU | 按任务选固定机型 |
| 适合 | 小数据集、试东西 | 长训练 |

云端这个选项，正是流程其余部分用笔记本就够的原因：本地录，训练甩出去。

### 策略的额外依赖

有些策略类型需要 LeLab 默认不装的依赖。选中时会问你要不要装——**等后台装完再启动任务**。可选的训练附加组件走同一个机制。

## Checkpoint

训练会**定期**写 checkpoint，不是只在最后写，所以中断的那轮也留着能用的模型。名字里带步数。loss 开始往上走就换早一点的试。

## 推理

打开 **Inference** 页：

1. 确认两条臂都接好、校准好。
2. 选**策略**——本地 checkpoint，或 Hub 上的模型。
3. 确认**摄像头**和它们的 **rotation**。
4. 开始推理，把工作台清干净。

### rotation 和绑定

**用录制时的那个 rotation。** 训练好的策略在真机上什么也不干，这是最常见的原因，而且**没有任何东西会提醒你**：0° 和 180° 的图片尺寸完全相同。

摄像头的**绑定**同理。录制时叫 `wrist` 的摄像头，现在换成另一个物理摄像头了，策略看到的就是错的画面。

都对还是不行，回头再看数据集——见[第 5 篇](05-Record-Dataset.md)。

### 中途干预

要伸手扶机械臂之前先停掉推理。手动做的纠正不是训练信号，除非你录成新 episode 再训练。

## 回放

回放把录过的 episode 在从臂上重播。它播的就是录下来的关节位置，所以**策略再烂回放也是对的**——它检查的是硬件和数据集，不是策略。要看策略怎么样，用推理。
