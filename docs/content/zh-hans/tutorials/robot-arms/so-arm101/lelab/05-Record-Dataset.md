# 5 · 录制数据集

> **上一篇**：[04 遥操作](04-Teleoperation.md)
> **下一篇**：[06 训练与推理](06-Train-and-Inference.md)

数据集是一堆 **episode** 的集合，每个 episode 是一次完整的演示。录制就是遥操作加一个录制控制。

## 录制前的设置

打开 **Recording** 页，填这几项：

| 项目 | 填什么 |
|---|---|
| **数据集名**（`repo_id`） | `your-name/task-name`，比如 `juxi/pick-up-the-cube`。以后要上传的话，前面的 `name/` 必须是你的 Hugging Face 用户名 |
| **任务描述** | 一句话，比如 `pick up the cube and drop it in the box`。这是策略的条件输入 |
| **Episodes** | 录多少个演示，见下 |
| **摄像头** | 用哪几个摄像头，以及分辨率和帧率 |

### 录多少个

简单抓放用 **30 到 50** 个。很重复的任务可以少些，变化多的要多些。

**一致性比数量重要**：每集的初始位置、取景、任务描述都要一样。五十个几乎一致的演示，胜过一个多样但每集都不同的数据集。只在希望策略具备鲁棒性的地方做变化——如果每集方块都在同一点，策略学到的就只有那个点。

## 录制过程中

| 按键 | 作用 |
|---|---|
| `SPACE` 或 `→` | 结束当前 episode，开始下一集 |
| `DEL` 或 `←` | 扔掉刚录的这一集，重录 |

页面上有 episode 计数和 session 计数。

**任务做完就结束 episode**，不要等机械臂回到起点——回到起点是下一集的事。

手滑了、把物体碰移位了、任务没做完，就该重录。策略会从数据集里的所有东西学，包括错误。

## 结束录制

攒够 episode 就停。**录制是在点停止时才收尾的**，数据集索引也在那一刻写下去。中途被杀掉的 session 可能留下一个读起来不完整的数据集。

## 数据存到哪

默认在 `~/.cache/huggingface/lerobot/` 下，以你填的 `repo_id` 命名。**这一步不上传任何东西**，直到你在 **Upload** 页推它。

## 录完先看一眼

打开 **Datasets** 页选中数据集，可以逐帧翻每个 episode，一次一个摄像头，旁边有关节运动曲线。

训练之前先看。这些是握着机械臂时察觉不到的：

- 摄像头旋转设错了——画面是歪的
- 某个 episode 开头录进了一长段等待
- 腕部摄像头拍到一半飘出画面

现在发现，代价是重录一遍；训练完才发现，代价是整轮训练。
