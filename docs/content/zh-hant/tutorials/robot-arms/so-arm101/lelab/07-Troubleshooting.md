# 7 · 疑難排解

> **上一篇**：[06 訓練與推論](06-Train-and-Inference.md)

依症狀分組。

## 頁面打不開，或某個埠被占用

**8000** 與 **8080** 是 LeLab 的埠。殘留程序是常見原因——你關掉終端機而不是用 `Ctrl+C` 所留下的那種。

```bash
lelab --stop
```

會釋放兩個埠。啟動前想確認：

```bash
curl http://localhost:8000/health
```

有 JSON 回應，就表示 8000 上有東西在跑。

## `--dev` 模式下頁面空白或 404

Vite 在 **:8080** 提供介面；API 在 **:8000** 執行。請瀏覽 `:8080`。`--dev` 下的 8000 埠只給你沒有介面的 API。

## 手臂沒有出現

檢查這些埠對你的使用者是否可見。在 Linux 上，缺少群組的表現就像手臂不存在：

```bash
ls /dev/ttyACM*
groups | grep dialout
```

如果缺少 `dialout`：

```bash
sudo usermod -aG dialout $USER
```

接著**登出再登入**——群組是在登入時讀取的，所以只開新終端機不夠。

### 只找到一條手臂

使用**兩個獨立的 USB 埠**，不要用集線器；兩條手臂列舉出來是同一種裝置，共用的集線器可能不穩定地呈現它們。要辨識某個埠，拔掉一條手臂，看哪個清單項目消失。

## 我每次都得重新校準

校準檔位於 `~/.cache/huggingface/lerobot/` 底下——也就是 `~/.cache/` 底下。清理快取的工具與容器重啟都會帶走它們。

- 把 `~/.cache/huggingface/lerobot/calibration/` 備份到耐久的地方。
- 在容器中，把該目錄掛載成 volume。

### 已校準的手臂行為異常，卻沒有要求重新校準

檢查所選的**設定檔**是否屬於該實體手臂。設定檔綁定一條手臂的零點；把手臂對調就表示要重新校準。

## 攝影機影像上下顛倒或歪斜

在[校準分頁](03-Calibration.md)設定攝影機的 **Rotation**：0°、90°、180° 或 270°，順時針。上下顛倒的腕部攝影機是 180°。

**90° 與 270° 會交換輸出尺寸**——640 × 480 的擷取會變成 480 × 640。

## 訓練好的策略毫無用處

依序檢查——前兩項遠比訓練不良常見：

1. **攝影機旋轉。** 確認推論使用的是錄製時所用的旋轉。0° 與 180° 的影像尺寸相同，所以不會有任何警示。
2. **攝影機綁定。** 如果錄製時名為 `wrist` 的攝影機現在是另一台實體攝影機，策略看到的就是錯誤的影像。
3. **起始位置與任務描述。** 推論必須從示範開始時的相同配置開始。
4. **Checkpoint。** 試試較早的一個。

## 用手機當攝影機

瀏覽器只在 **HTTPS** 下授予攝影機存取權（`getUserMedia`），`localhost` 除外，因此透過區域網路連線的手機會被拒絕。

設定指南：[`frontend/HTTPS_SETUP.md`](https://github.com/Juxi-Technology/leLab/blob/main/frontend/HTTPS_SETUP.md)。憑證是自簽的，因此瀏覽器會顯示警告，接受即可。

預設安裝**不會**以 HTTPS 啟動；手機攝影機需要用該文件所述的憑證參數手動啟動。

## 資料集打不開——「尚未下載」

LeRobot 在錄製**正常結束**時寫入資料集索引。在 episode 中途被終止的 session，可能留下一個看起來完整、實際卻不完整的目錄。episode 資料通常還在磁碟上；缺的是索引。重錄該 session，並用停止按鈕將它停止。

## 訓練說某個套件遺失

有些策略類型與可選的訓練功能需要預設未安裝的相依套件。當你選取其中一項時，Training 分頁會提議安裝它們；等背景安裝完成後再啟動任務。如果你想手動安裝，訓練日誌會寫出套件名稱。

## 沒有出現更新通知

這是刻意設計：此檢查只適用於從 git 安裝的版本。**可編輯安裝**（`pip install -e .`）是工作副本，不列入檢查。這類請用 `git pull` 更新。

## 還是卡住

蒐集**瀏覽器主控台**與**執行 `lelab` 的終端機**——伺服器會記錄失敗的那個請求。這些失敗大多與你最後更動的東西只隔一步。
