# 7 · 문제 해결

> **이전:** [06 학습과 추론](06-Train-and-Inference.md)

증상별로 정리했습니다.

## 페이지가 열리지 않거나 포트가 사용 중인 경우

포트 **8000**과 **8080**은 LeLab의 것입니다. 흔한 원인은 오래된 프로세스입니다 — `Ctrl+C`가 아니라 터미널을 닫아 종료한 것입니다.

```bash
lelab --stop
```

두 포트를 모두 해제합니다. 시작 전에 확인하려면:

```bash
curl http://localhost:8000/health
```

JSON 응답이 오면 8000에서 무언가가 실행 중입니다.

## `--dev` 모드에서 페이지가 비어 있거나 404인 경우

Vite는 **:8080**에서 UI를 제공하고 API는 **:8000**에서 실행됩니다. `:8080`을 여십시오. `--dev`에서 포트 8000은 UI 없는 API입니다.

## 팔이 나타나지 않는 경우

사용자에게 포트가 보이는지 확인하십시오. Linux에서는 그룹이 없으면 팔이 없는 것처럼 보입니다:

```bash
ls /dev/ttyACM*
groups | grep dialout
```

`dialout`이 없다면:

```bash
sudo usermod -aG dialout $USER
```

그런 다음 **로그아웃했다가 다시 로그인**하십시오 — 그룹은 로그인 시 읽히므로 새 터미널로는 부족합니다.

### 팔이 하나만 발견되는 경우

**분리된 USB 포트 두 개**를 사용하고 허브는 사용하지 마십시오. 두 팔은 같은 종류의 장치로 열거되며 공유 허브는 이를 불안정하게 표시할 수 있습니다. 포트를 식별하려면 팔 하나를 뽑고 어느 목록 항목이 사라지는지 확인하십시오.

## 매번 다시 캘리브레이션해야 하는 경우

캘리브레이션 파일은 `~/.cache/huggingface/lerobot/` 아래, 즉 `~/.cache/` 아래에 있습니다. 캐시 정리 도구와 컨테이너 재시작이 이 파일들을 가져갑니다.

- `~/.cache/huggingface/lerobot/calibration/`을 안전한 곳에 백업하십시오.
- 컨테이너에서는 이 디렉터리를 볼륨으로 마운트하십시오.

### 캘리브레이션한 팔이 다시 캘리브레이션을 요구하지 않으면서 이상하게 동작하는 경우

선택한 **프로필**이 그 물리적 팔의 것인지 확인하십시오. 프로필은 한 팔의 영점에 묶여 있으므로, 팔을 서로 바꾸면 다시 캘리브레이션해야 합니다.

## 카메라 이미지가 거꾸로 또는 옆으로 나오는 경우

[캘리브레이션 탭](03-Calibration.md)에서 카메라의 **Rotation**을 설정하십시오: 0°, 90°, 180°, 270°(시계 방향). 거꾸로 장착한 손목 카메라는 180°입니다.

**90°와 270°는 출력 크기를 바꿉니다** — 640 × 480 캡처가 480 × 640이 됩니다.

## 학습된 정책이 유용한 동작을 하지 않는 경우

순서대로 확인하십시오 — 처음 두 가지가 나쁜 학습 실행보다 훨씬 흔합니다:

1. **카메라 회전.** 추론이 녹화 시 사용한 회전을 사용하는지 확인하십시오. 0°와 180°는 이미지 크기가 동일하므로 아무것도 경고하지 않습니다.
2. **카메라 바인딩.** 녹화 중 `wrist`로 명명한 카메라가 이제 다른 물리적 카메라라면 정책은 잘못된 이미지를 봅니다.
3. **시작 위치와 작업 설명.** 추론은 시연이 시작한 배치에서 시작해야 합니다.
4. **체크포인트.** 더 이른 것을 시도하십시오.

## 휴대폰을 카메라로 사용하는 경우

브라우저는 `localhost`를 제외하고 **HTTPS**에서만 카메라 접근(`getUserMedia`)을 허용하므로, LAN으로 연결한 휴대폰은 거부됩니다.

설정 가이드: [`frontend/HTTPS_SETUP.md`](https://github.com/Juxi-Technology/leLab/blob/main/frontend/HTTPS_SETUP.md). 인증서는 자체 서명이므로 브라우저가 수락할 경고를 표시합니다.

기본 설치본은 HTTPS로 시작하지 **않습니다**; 휴대폰 카메라에는 거기 설명된 인증서 플래그로 수동 시작이 필요합니다.

## 데이터셋을 열 수 없음 — "not downloaded yet"

LeRobot은 녹화가 **정상적으로 끝날 때** 데이터셋 인덱스를 기록합니다. 에피소드 도중 종료된 세션은 완전해 보이지만 그렇지 않은 디렉터리를 남길 수 있습니다. 에피소드 데이터는 보통 디스크에 남아 있고, 빠진 것은 인덱스입니다. 세션을 다시 녹화하고 중지 버튼으로 중지하십시오.

## 학습에서 패키지가 없다고 하는 경우

일부 정책 유형과 선택적 학습 기능은 기본으로 설치되지 않은 종속성이 필요합니다. Training 탭에서 하나를 선택하면 설치를 제안합니다. 백그라운드 설치가 끝날 때까지 기다린 뒤 작업을 시작하십시오. 직접 설치하고 싶다면 학습 로그에 패키지 이름이 나옵니다.

## 업데이트 알림이 표시되지 않는 경우

설계상 그렇습니다: 검사는 git에서 설치한 경우에만 적용됩니다. **편집 가능 설치**(`pip install -e .`)는 작업 복사본이며 검사하지 않습니다. `git pull`로 업데이트하십시오.

## 그래도 해결되지 않는 경우

**브라우저 콘솔**과 **`lelab`을 실행 중인 터미널**을 수집하십시오 — 서버가 실패한 요청을 기록합니다. 이러한 실패는 대부분 마지막으로 변경한 것에서 한 단계 떨어져 있습니다.
